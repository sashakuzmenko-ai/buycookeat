# Cook & Eat — план робіт після аудиту концепту

Складено 13 листопада 2026 за аудитом коміту `0d33d35` (`main`). Джерело правди для дизайну —
[docs/design/README.md](design/README.md) і `docs/design/concept/*.dc.html`.

Порядок етапів — це порядок виконання. Етап 0 робить власник руками, решта — задачі для реалізації.

## Стан на момент аудиту

Перевірено: `npm run lint`, `npm run check`, `npm run build` проходять; токени, шрифти, знак, навігація й
обов'язкові елементи восьми модулів відповідають концепту (оцінено за кодом; наживо переглянуто лише
сторінку входу). Ключ OpenRouter робочий, бот `@CookingFamilyBot` відповідає.

Не працює:

| Що | Факт |
|---|---|
| База | У Supabase немає міграцій `20261112000000` і `20261113000000`: відсутні `receipts`, `receipt_items`, `incoming_scans`, `channel_bindings`, `pantry_movements`, колонки `storage_zone`, `expires_at`, `monthly_budget`, `restrictions`. |
| Ключ бота до бази | `SUPABASE_SECRET_KEY` не заданий ні локально, ні в продакшні. |
| Змінні у Vercel | Продакшн відповідає 503: не бачить `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `SUPABASE_SECRET_KEY`. |
| Webhook | `getWebhookInfo` повертає порожню адресу. |

### Бот для двох уже зараз

Прив'язка в боті — це пара «чат ↔ обліковий запис». Один обліковий запис може мати лише один прив'язаний чат,
але чатом може бути група. Тому при спільному логіні схема така:

1. Створити в Telegram окрему групу лише для бота (наприклад, «Дім · Cook & Eat»), додати дружину і `@CookingFamilyBot`.
2. У BotFather: `/setprivacy` → Disable. Якщо бота додали до групи раніше — видалити й додати знову, інакше налаштування не застосується.
3. У застосунку: «Сім'я» → згенерувати код → надіслати в групу `/start КОД` (код діє 20 хвилин).
4. Далі обоє надсилають у групу чеки, голосові, відео полиці, скріншоти й текст; кнопки під відповіддю може натискати будь-хто з групи.

Обмеження цієї схеми, які знімає етап 1:

- особисті чати з ботом не працюватимуть ні у вас, ні в дружини — лише група;
- бот сприймає **кожне** текстове повідомлення в групі як список для розпізнавання, тому група має бути лише для бота;
- у застосунку всі скани виглядають як надіслані одним користувачем.

## Етап 1. Telegram для всієї сім'ї

Мета: і ви, і дружина користуєтесь ботом і в особистому чаті, і в сімейній групі, при одному спільному логіні.

### 1.1 Кілька чатів на один обліковий запис

Зараз `createTelegramLink` (`src/app/(app)/settings/actions.ts`) нічого не робить, якщо прив'язаний чат уже є,
а `unlinkTelegram` видаляє всі прив'язки користувача.

- Дозволити видавати новий код, коли прив'язані чати вже є. Очікувальний рядок більше не може мати
  `external_id = pending:<userId>` один на користувача — потрібен унікальний на кожен код.
- У картці «Доступ і Telegram» показати список прив'язаних чатів (назва, тип: особистий чи група, дата) і
  кнопку «Відв'язати» для кожного окремо.
- Зберігати назву чату й тип: нові колонки в `channel_bindings` (`title`, `chat_type`) — окрема міграція.
- Критерії: з одного логіна прив'язано два особисті чати й одну групу; відв'язка одного не чіпає інших;
  `npm run check` покриває: другий код не гасить перший чат, чужа сім'я не бачить прив'язок.

### 1.2 Поведінка в групі

Зараз будь-який текст без медіа йде в розпізнавання (`src/lib/channels/turn.ts`, остання гілка `handleTelegramUpdate`).

- У групі бот реагує лише на: медіа, команди, швидкі запити («Що на вечерю?», «Список покупок», «Залишки»),
  згадку `@бот` і відповідь на власне повідомлення. Звичайну розмову ігнорує.
- В особистому чаті поведінка не змінюється.
- Посилання прив'язки для групи: `https://t.me/<бот>?startgroup=<код>` поруч із наявним `?start=<код>`.
- Критерії: логічний тест на тип чату — текст у групі без згадки не створює скан; той самий текст в особистому створює.

### 1.3 Хто надіслав

- Зберігати ім'я відправника з Telegram у метаданих скану (`incoming_scans`, поле каналу) і показувати його в
  черзі «Скан» та в «Останніх сканах» на «Огляді»: «Чек · Сільпо · від Олени».
- Критерії: два різні відправники з однієї групи дають два скани з різними іменами.

### 1.4 Перевірка наживо

- Сценарій із `MTelegram.dc.html` на продакшні: голосове → «У покупки» / «Уже купили»; фото чека → «Усе так,
  записати»; три швидкі запити. Зафіксувати результат у `wiki/tasks/`.

## Етап 2. Telegram-функції з концепту, яких немає

- **2.1 «Надіслати список у Telegram»** (`WebShops.dc.html`). Кнопка на `/shopping` надсилає поточний список,
  згрупований за магазинами, у всі прив'язані чати сім'ї. Без прив'язки — підказка з посиланням на «Сім'ю».
- **2.2 «Попереджати в Telegram, коли темп вищий за план»** (`WebFamily.dc.html`). Перемикач у картці бюджету
  (нова колонка в `households`). Повідомлення надсилається після підтвердження чека, якщо темп перейшов межу,
  не частіше одного разу на день. Планувальник не потрібен.

## Етап 3. Решта розбіжностей із концептом

- **3.1 Запрошення до сім'ї.** Зараз «Запросити за посиланням» копіює адресу сайту, а нова людина після
  реєстрації отримує окрему сім'ю. Потрібні: одноразове посилання-запрошення з терміном дії, приєднання до
  наявної сім'ї замість `create_household`, RLS-перевірка в `check-sql.mjs`. Не терміново, поки логін спільний;
  до того часу кнопку варто або прибрати, або чесно підписати.
- **3.2 Імпорт рецепта за посиланням** (`WebRecipes.dc.html`). Сторінка → OpenRouter → чернетка у формі рецепта
  для перевірки перед збереженням.
- **3.3 Перетягування страв між днями** в меню (`WebMenu.dc.html`), з клавіатурною альтернативою «Перенести на…».
- **3.4 «Заповнити порожнє» з урахуванням складу й техніки.** Зараз це підбір за правилами з власних рецептів.
  Рішення власника: лишити правила чи підключити OpenRouter.
